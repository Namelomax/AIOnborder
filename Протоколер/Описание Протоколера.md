# **ИИ-ассистент для подготовки протоколов обследования**
**Версия документа:** 1.0

## **1. Цель проекта**
Создать интеллектуального ассистента, который автоматизирует подготовку протоколов обследования на основе записей и расшифровок встреч с заказчиком:
- **Сократит время** подготовки протоколов с 1–2 дней до нескольких часов.
- **Минимизирует человеческие ошибки** при фиксации договорённостей.
- **Повысит качество** проектной документации за счёт точного отражения хода обсуждения.

## **2. Что войдёт в систему?**

### **2.1. Обработка записей встреч**

| Функция                 | Что включает?                                                    | Пример                                                          |
| ----------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------- |
| **Загрузка записей**    | Приём аудио/видеозаписей или готовых текстовых расшифровок       | «Аналитик загружает запись встречи в формате MP3/WAV или текст» |
| **Транскрибация**       | Автоматическое преобразование аудио в текст с разметкой спикеров | -                                                               |
| **Разметка тайм-кодов** | Привязка фрагментов обсуждения к временным меткам                | «[00:15:32] Обсуждение требований к интеграции с 1С»            |

### **2.2. Генерация протокола обследования**

| Раздел протокола             | Что включает?                                     | Пример                                                       |
| ---------------------------- | ------------------------------------------------- | ------------------------------------------------------------ |
| **Участники**                | Список участников встречи, их роли                | «руководитель проекта, заказчик»                             |
| **Повестка**                 | Перечень обсуждавшихся вопросов                   | «1. Требования к модулю интеграции; 2. Сроки поставки»       |
| **Обсуждение**               | Структурированная фиксация хода дискуссии         | -                                                            |
| **Решения и договорённости** | Зафиксированные итоги с указанием ответственных   | -                                                            |
| **Открытые вопросы**         | Вопросы, оставшиеся без ответа                    | «Не определён бюджет на закупку лицензий»                    |
| **Уязвимые места**           | Фрагменты с пометками о неточностях и тайм-кодами | «⚠ [00:42:10] Возможно неверно зафиксирован ответ заказчика» |

### **2.3. Контроль качества**

| Категория | Что включает? | Пример |
|---|---|---|
| **Выявление противоречий** | Поиск несогласованных утверждений в ходе встречи | «В [00:10:00] заказчик сказал "до конца квартала", в [00:45:00] — "до конца года"» |
| **Отделение фактов от предположений** | Маркировка утверждений, не подтверждённых заказчиком | «⚠ Данное утверждение — предположение члена проектной команды, не подтверждённое заказчиком» |
| **Проверка полноты** | Сопоставление повестки с зафиксированными решениями | «По пункту 3 повестки решение не зафиксировано» |

**Как это поможет аналитику:**
1. Не упустит важные детали в ходе обсуждения.
2. Исключит подмену ответов заказчика предположениями команды.
3. Получит готовый структурированный документ для доработки.

### **2.4. Навигация по документам проекта**
- Привязка протокола к проекту и предыдущим встречам.
- Поиск по ранее зафиксированным решениям и договорённостям.
- Формирование сводной **аналитической записки** на основе серии протоколов. (Этап 2)

### **2.5. Требования к продукту**
- Экспорт протоколов в формат **DOC/DOCX** для последующего редактирования.
- Точность генерации документов — **97%+**.
- Локальное размещение внутри компании.
- Поддержка контейнеризации и горизонтального масштабирования.

## **3. Путь пользователя**

### **3.1. Для аналитика**
1. Загружает запись встречи (аудио/видео) или текстовую расшифровку.
2. Система создаёт проект протокола с тайм-кодами и пометками об уязвимых местах.
3. Аналитик и проектная команда дорабатывают документ.
4. Итоговый протокол сохраняется в системе и привязывается к проекту.

### **3.2. Для руководителя проекта**
- Просматривает сводку решений и открытых вопросов по всем встречам проекта.
- Получает аналитическую записку на основе серии протоколов.
- Видит историю изменений и доработок протоколов.

### **3.3. Для команды**
- Доступ к актуальным протоколам по проекту.
- Возможность оставлять комментарии и уточнения.
- Поиск по базе зафиксированных договорённостей.

## **4. Технические особенности**
- **Фронтенд**: React (веб-интерфейс).
- **AI**: AI SDK с поддержкой различных LLM (GPT-4, LLaMA 3 и др.).
- **База данных**: SurrealDB.
- **Развёртывание**: Docker-контейнеры, горизонтальное масштабирование.
- **Безопасность**: Локальное размещение, доступ только для авторизованных сотрудников.

## **5. Что получит заказчик?**
1. **Сокращение времени** подготовки протоколов с 1–2 дней до нескольких часов.
2. **Повышение точности** — исключение упущений и ошибочных интерпретаций.
3. **Единая база знаний** — все протоколы и решения в одном месте.
4. **Аналитика** — автоматическое формирование записок по результатам серии встреч.

> «Система поможет аналитикам сосредоточиться на содержании встреч, а не на механической работе по составлению протоколов».
